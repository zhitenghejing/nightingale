# 环境关联首期和二期实际测试报告

## 目标完成情况

首期和二期约定的环境关联能力已实现，并通过程序测试、真实数据库、隔离运行实例、真实模型和浏览器检查。Agent能够查询已维护的具体业务链路，并结合实时数据说明事实与缺口。人工验收和医院真实环境试点尚未执行。

此前已完成功能先存档为提交 `5b14b433`。本次未推送、合并或发布到生产。

## 开发范围

首期实现：Target、采集设备、资产、正式资料版本的来源引用；按业务组维护业务对象；人工部署、依赖、所属、监控映射及资料描述关系；统一的环境关联弹窗；两个会话模式中的只读环境工具。

二期实现：按正式资料保存人的权限自动提取精确标识提及候选，定期对账和重试；候选人工确认/拒绝；来源变化、删除、换版、撤权和有效期检查；最多三层的有向关系查询；最近七天的精确对象历史告警和CMDB台账审计。环境/实时结论增加工具外核验，避免把空结果、目录截断或离散采样点扩大为全环境结论。

前端沿用原有框架：只在设备详情工具栏、CMDB设备弹窗、资料阅读抽屉增加“环境关联”按钮；弹窗使用现有Ant Design样式，不新增菜单。可维护业务对象、关联、候选，查看依赖及相关事件。

## 联调中发现并修复的问题

1. 新组件的请求依赖使四组原页面测试无法加载，补齐网络依赖模拟后24项原有用例通过。
2. 抽屉内弹窗被遮挡，调整弹窗、下拉框和确认提示层级，并限制内容高度。
3. 权限拒绝及切换对象时可能保留旧选项/迟到结果，清理缓存并按请求代次控制展示。
4. 采集配置指纹补入端口、协议和启用状态；未解析资料给出明确处理状态。
5. 模型首轮重复读取辅助信息耗尽额度，改为复用身份、优先依赖遍历与实时检查；补充结论核验，收窄空结果、目录截断和采样连续性的表述。

脚本中的控件定位、双字按钮空格和视口调用也已修正；最终从完整脚本重新执行，未把失败运行计为通过。
