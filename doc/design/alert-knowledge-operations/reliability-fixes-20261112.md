# 处置可靠性修复与验收记录

本轮承接 2026-11-12 真实 MiniMax 与 shared-prometheus 复测中发现的问题，依次修复操作前置门禁、无知识分支、提案后暂停、目标属性映射、模型输出协议及失败交接。不会把真实指标的链路测试解释成医院故障修复；真实 Ibex、医院业务、CMDB/变更适配仍是独立工作。

## 设计与兼容性

- 操作门禁在 `pkg/ops/prerequisites.go` 内，由准备与批准共同调用。旧版本未指定 required_steps 时要求全部步骤；分支版本可显式指定。最新步骤必须完成，证据须同处置/阶段/依据且成功、新鲜。失败/跳过、过期、背景变化均阻断，审批不能消费失败提案。
- 无知识时使用 `PreparePlan` 从原始快照提取最多两个限定 ident 的命名指标查询，不列举全部指标。平台上下文不是健康或根因证明；工具空结果继续保持 empty。单独的草稿生成阶段最多两次且共用期限，只开放不可执行的结构化输出格式，返回调用只作为 JSON 数据解析、不分发；来源与模型元信息可追溯；模型不可用时仅保留无修复动作的待完善排查提纲。自动方案的条件与指标查询必须来自当前已知输入，并包含人工业务/完整性核验。
- `ToolInterrupt` 在提案成功后立即停轮，阻止同批后续查询；已有有效待确认项时启动排查也不再取证。后台新增终态 awaiting_operator，不会自动重跑；人员确认、核实结果后可在页面继续排查。
- 匹配属性从处置主字段合并 target_ident/datasource_id/rule_id/group_id，覆盖同名背景输入；环境与版本仍不猜测。知识采用、方案条件和后续执行共用属性定义。
- `pkg/modeloutput` 只解析完整 JSON 对象及受支持包裹，过滤完整、嵌套和不完整思考块；旧运行记录只修改读取投影，不改历史原件。无可见模型结论按失败交接处理。
- 运行失败释放唯一活动占位，保存证据引用与下一接手角色；账号权限撤销仍可由 worker 完成状态回收。背景变化取消并 fencing 旧运行，旧结果不能覆盖人工输入。
- 页面增加操作必需检查选择、等待原因及等待接手状态；实际门禁仍以服务端为准。
- 新字段位于既有 JSON 内，运行状态继续使用现有 varchar；没有增表/增列或 SQL 迁移。未修改 edge/alert 公共读取或 plus 调用签名。

## 回归与审查

新增回归先复现缺失门禁、目标匹配错误和草稿解析失败，再验证修复。专项覆盖：前置结果在批准前转失败、指定分支、过期证据、无知识/空指标、真实执行器同批暂停、格式失败提纲、人工背景并发修改、权限撤销、历史结果过滤。既有动作正向用例补足前置检查，未删除或跳过原断言。

按调用链审查：原生事件→处置作用域→来源查询→证据→方案/知识→动作→人员端批准→恢复→结束。重点检查了 case/run 加锁顺序、fence、跨组/跨目标边界、提纲不冒充已验证方法、模型参数与输出不包含凭据，以及旧不可变 JSON 的兼容读取。

工程门禁、真实模型结果和内网浏览器记录在最终交付报告中逐项给出，失败/跳过/人工验收分别报告。修复前的工程门禁曾因测试仍断言“取消运行的读取结果为空”失败；修复后保持数据库原结果为空，读取投影提供明确占位提示，回归同时核对数据库及页面语义。

真实模型回归进一步复现状态名重复尝试及自由文本草稿不稳定，补齐步骤状态枚举、成功回执和操作就绪提示，并把草稿输出改成带字段约束的提交格式。运维权限没有增加；未知函数名、多次提交及无效 JSON 均拒绝。无知识方案仅使用本轮查询和新鲜人工证据，不把旧猜测混入本轮事实。
