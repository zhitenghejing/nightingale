# 设备监控页面原型

问题：从常规运维巡检视角，如何快速发现设备异常、区分设备不可达和采集故障，并进入数据与告警定位？

这是独立的、可丢弃的设计研究。沿用相邻模板中心原型的发布方式；当前 hosts 页面和采集模块已有大量开发中修改，暂不挂入生产路由。复用夜莺的导航上下文、紫色主题、设备分组和模板概念，不改变现有功能。

## 打开与运行

直接打开 [prototype.html](prototype.html)，不需要依赖、登录或后端。

发布到当前分支的隔离预览，并逐文件保留已有业务 UI、架构图和其他原型：

```bash
python3 -B doc/design/device-monitoring-prototype/publish.py
```

此分支遵守 [LAN 测试约定](../../worktree-preview.md#snmp-分支本地测试约定)，使用 `http://192.168.0.152:30304/prototype/device-monitoring.html?variant=A`。发布脚本保留 `/tmp/n9e-monitoring-prototype-*` 作为预览资源来源，实例使用期间不可清理该目录。

## 三个布局

| 方案 | 信息组织 | 适用场景 |
| --- | --- | --- |
| A：设备总表（推荐默认） | 左侧分组、高密度设备列表、行内状态和入口 | 日常巡检与设备定位 |
| B：告警优先工作台 | 严重事件优先，右侧设备上下文 | 值班和故障响应 |
| C：分组巡检 | 以业务组或机房为单位逐块巡检，可钻取到 A | 按范围巡检 |

底部浮条或左右方向键切换方案，`?variant=A|B|C` 可分享并在刷新后保持。输入框、选择器和详情弹层内不截获方案切换键。三种方案保留同一份内存筛选状态。

参考 [Zabbix 官方 Monitoring → Hosts 文档](https://www.zabbix.com/documentation/current/en/manual/web_interface/frontend_sections/monitoring/hosts)：设备列表展示接口、可用性、标签、当前问题和启停状态，提供最新数据、问题、图表、仪表盘等入口。本原型借鉴设备行的监控入口和密度，增加资源摘要与数据新鲜度；机房与业务组承担本轮范围筛选，任意标签表达式暂未设计。

## 状态定义与设计审查

- 可达性：ICMP 探测结果，不代指所有服务的健康状态。
- 采集状态：协议采集与数据新鲜度，与 ICMP 分列。`access-sw-sh-02` 展示 ICMP 可达但 SNMP 采集失败。
- 当前告警：未恢复事件。`prod-db-mysql-01` 展示采集正常但存在业务告警；确认仅表示接手，不能恢复或删除事件。
- 维护：保留事件，默认抑制展示，可勾选查看。停用：不参与健康判断。未知：没有当前检测结果。
- 缺失 CPU、内存数据使用“—”，不回填为 0 或展示过期值。最近采集列帮助识别陈旧数据。
- 统计卡作用域是当前分组，卡片可继续筛选；搜索、类型、采集状态和告警级别叠加到列表。数量全部来自同一份 12 台设备的模拟集合。

设计取舍：默认页面优先回答“哪些设备需要关注”和“下一步去哪看”。新增设备、模板编辑和采集配置属于管理任务，本页不承担配置向导。资源图表只展示设备详情中的 CPU 示例，其他专属图表待模板能力对接。B/C 提供结构比较，尚未经人工选择，不代表已确定生产方案。

## 可操作验收

1. A 默认显示 12 台设备、5 台有告警、1 台不可达、2 台采集异常、2 台维护或停用。点击统计卡与分组检查联动。
2. 搜索 `access-sw`，应仅显示可达但采集异常的交换机；输入无匹配内容出现空态，重置可恢复。
3. 点击设备名查看概览；点击数据、图表、仪表盘或告警进入相应详情。详情内切换标签，使用 Escape 或点击遮罩关闭。
4. 在最新数据内搜索指标。无新鲜采集的资源指标显示“—”，探测结果仍独立展示。
5. 勾选设备，进入/退出维护（模拟）；维护中的事件仍保留。开启“显示维护中被抑制的告警”可查看。
6. 切换 B，确认待处理告警（模拟），应显示已确认，告警数量不减少。
7. 切换 C，选择某分组“查看列表”，应回到 A 并保留相同分组。
8. 刷新浏览器应复位所有模拟操作，仅 URL 方案保留。

## 边界

所有数据为模拟，全部动作仅在内存中，不读写设备、监控 API、数据库或通知通道。侧边全局导航是上下文示意。未执行生产接入、发布或人工验收。原型无生产构建入口，底部方案切换器仅存在于独立设计 HTML。选定方案后需要按正式前端规范重新实现，再捕获设计决定并清理原型。
