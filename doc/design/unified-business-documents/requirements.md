# 档案管理功能需求

版本：v0.3。状态：列表、业务规则、双模式与 Word 版式验收边界已确认，进入真实开发。适用分支：`feat/feature-planning`。

新增一级菜单“档案管理”，整合培训服务、巡检报告、故障报告，保留原有三类业务的字段和 Tab 名称。统一提供多份资料留档、整页阅读、上传 Word 转为在线文档编辑、PDF 阅读与批注，以及从空白创建文档。在线文档也可以属于新的类型，不局限于原三类。

## 3 菜单与页面组织

### 已确定的页面结构

一级菜单为“档案管理”。原有三个 Tab 名称保持为“培训服务”“巡检报告”“故障报告”，另有“其他文档”。每个 Tab 有自己的查询条件、列表与新建入口。列表采用已确认的方案 A，保留 main 的菜单、表格、操作栏和主题风格；不把 B/C 的布局带入正式页面。

阅读和编辑使用独立整页，允许直接打开和刷新；返回列表时保留页签、筛选条件和分页。业务信息、文档列表可收起，避免挤占长文档阅读和编辑区域。简短的业务字段编辑可以使用弹窗或抽屉。

### 其他文档入口

已确认增加第四个 Tab“其他文档”，用于原三类以外的文档；其中“文档类型”允许手填新类型并复用已有输入。不增加第二个菜单入口。

新类型只需最小信息：标题、类型、文档状态、内容或资料、创建/更新信息；不要求填写培训、巡检或故障字段。首版不增加分类管理后台，也不扩展可配置字段模板。

| 页面 | 主要内容 |
| --- | --- |
| 列表 | 当前类别筛选、业务摘要、资料数量、状态、更新时间、新建及记录操作。 |
| 档案详情 | 完整业务字段、文档与附件、用途、版本及操作日志。 |
| 阅读页 | 正文或文件、目录/页码、查找、缩放、书签、适用的批注、下载/打印。 |
| 编辑页 | 文档编写、排版、保存状态、版本、编辑占用状态和返回入口。 |

## 4 档案与文档的关系

| 概念 | 本轮采用的含义 |
| --- | --- |
| 档案记录 | 一次培训、一次巡检、一次故障报告或一份其他类型档案，包含相应业务信息。 |
| 文档项 | 一份上传文件或一份在线文档。可有多份，分别标明讲义、签到、报告或其他资料等用途。 |
| 在线文档 | 从空白创建或由 Word 导入的可编辑内容；不等同于原始 Word 文件。 |
| 版本 | 业务信息、文档正文、附件或 PDF 批注经过正式保存形成的可追溯内容。 |

同一档案允许在线文档和上传文件并存。可选一份主文档，打开阅读时优先展示；其他资料仍可切换。新档案首次添加的可阅读文档作为初始主文档，允许后续指定；无主文档时进入资料列表。

业务字段与正文分别维护。修改培训地点不会自动改写讲义正文，编辑巡检报告也不自动改变巡检结果。首版不做字段自动套入文档模板。

首版不增加“同一文档在多条档案间实时引用”的能力；向不同档案上传同一文件，按各自独立资料管理，防止一处替换改变另一处的留档内容。

## 5 业务字段规则

### 共通信息

保留系统维护的创建人、创建时间、最后修改人、更新时间；增加档案状态、文档用途与版本信息。不额外要求选择客户、项目或业务组，不增加与本轮无关的负责人字段。

培训以“培训主题”为记录标题，巡检以“巡检名称”为标题。故障列表可以用影响业务与发生时间组合显示摘要，不要求另填截图没有的故障标题。在线文档自身有独立标题。

截图中已有红星必填字段保留。其余业务字段先保留为可填写项，不把“附件必填”扩展为全部业务字段都必填。草稿可暂缺资料，归档时校验正式材料，见第 11 节。

### 培训服务

## 6 列表查询与详情操作

各 Tab 保留原筛选，提供查询、重置、分页、排序、加载及空结果提示。其他文档按标题、手填类型和状态查询。支持选择当前页记录执行批量删除，明确显示数量，不默认选中全部匹配记录。

详情中的操作分别命名为“编辑业务信息”“在线编辑”“替换文件”“阅读”“下载”“归档”“版本”“操作日志”。各账号获得相同的功能入口，但同一文档的并发编辑仍由编辑锁控制。

首版提供本页业务字段及文档标题查询、阅读页的文内查找，不做跨类别统一搜索、全部附件全文索引或报表统计。

## 7 文件限制上传与替换

### 已按授权确定的初始限制

用户已授权 Agent 制定文件大小与数量限制，本版采用以下初始值；未来可通过部署配置调整，不新增面向操作者的配额管理后台。

| 对象 | 初始限制与计算方式 |
| --- | --- |
| 单个上传文件 | 50 MiB，按文件实际字节数检查。 |
| 每条档案的文档项 | 最多 20 份；上传文件与在线文档合并计算，讲义和签到等不同用途共用此上限。 |
| 每条档案的当前资料总量 | 500 MiB，包含当前文件、在线正文及其内嵌图片等媒体。 |
| 单份在线正文 | 正文内容最多 5 MiB，不把图片以正文中的内嵌编码重复计算。 |
| 编辑器插入的单张图片 | 10 MiB，计入所属档案的资料总量；不单独占用一个文档项名额。 |
| 替换或历史版本 | 替换不占新增文档项名额；旧版本另行保留，不计当前资料的 500 MiB，但仍占真实存储空间，不因达到当前配额自动删历史。 |

MiB 为 1024 × 1024 字节。以上是首版容量规则，不代表未经样本验证的性能承诺。存储不足时明确拒绝新的保存并保留已存在内容，不自动删除历史资料腾出空间。

### 上传行为

上传显示名称、用途、格式、大小、进度和成功/失败结果，支持取消与失败重试。损坏、加密或不支持的文件明确说明原因，不能以空白页当作预览成功。

完成归档前检查必交资料；自动草稿允许资料尚未齐全。归档后替换仍保留原有历史和操作日志，不允许替换后使必交资料缺失。

同名文件可以存在，文件名不作为唯一身份。区分“更改显示名”“替换文件”“编辑在线内容”；替换明确告知影响哪份资料，生成新版本。

上传成功但记录未保存的临时资料有独立状态；取消后不出现在正式档案中，确认无引用后才可清理。具体临时清理周期留到实施设计，不能清理已经保存的版本。

### 文件范围

已确认首版接收 DOCX、PDF、PNG、JPG/JPEG，以及本系统在线文档。Word 导入在线正文，PDF 保持原页阅读并批注，图片直接阅读。另已确认同一在线文档可视化/Markdown 双向编辑；首版不做独立 .md 上传下载，正式导出为 PDF/DOCX。旧版 DOC、Excel、PPT、普通 TXT 不纳入首版。

## 8 阅读模式

阅读页支持宽屏和全屏，业务信息与附件导航可收起。能切换同档案的多份资料，查看当前文档名、用途、格式、版本和来源，退出后返回原位置。

| 内容 | 阅读能力 |
| --- | --- |
| PDF | 连续/分页阅读、页码、翻页、跳页、缩略图、缩放、适合宽度/整页、文字层查找、书签、批注。 |
| 在线文档 | 正文排版、标题目录、表格、图片、文内查找、合适的阅读宽度与字号、分页与全屏。 |
| Word 导入结果 | 转成在线文档后阅读，明确它是导入结果，可同时定位原始 Word。 |
| 图片 | 等比缩放、移动查看、适合窗口、原图查看；按附件顺序切换。 |

PDF 批注首版包含高亮、划线和定位到页/位置的文字备注；可新增、修改、删除并保存。批注随文件版本关联，换文件不把旧位置的批注错误套到新内容上。所有账号可编辑共享批注，但每次修改保留操作者和日志；编辑批注也遵循文档独占锁。

书签保存为个人阅读位置；档案内容、文档版本和批注按统一共享资料管理。个人书签不是业务权限隔离。普通阅读不需要抢占编辑锁。

提供加载、转换中、失败、重试和下载状态。扫描 PDF 的图片阅读不受影响；首版不做 OCR，也不提供图中文字检索。不把没有文字层的图片文档标成可全文搜索。

## 9 上传 Word 转为在线文档

采用用户接受的“导入为在线文档后编辑”，首版不要求直接在原始 Word 文件内写回，也不引入多人协作 Office 编辑范围。

原始上传件保留，导入产生与原件有关联的在线内容，二者明确区分。用户先查看转换结果，再编辑和保存。基本文本、标题、表格和图片应保留到可编辑状态；用户已确认：以可编辑内容完整和系统内输出一致为准；复杂布局先展示转换结果再确认，不承诺与原 Word 逐页、逐像素一致。

编辑保存产生在线文档的新版本；导出 PDF/DOCX 来自当前编辑内容，不能把最初上传件冒充当前编辑稿。下载原件继续得到该次上传的原始字节。

PDF 不转换为可改原文的在线正文，保留文件页式阅读及独立批注版本；首版不做直接修改 PDF 原文字或表单填写功能。

## 10 从空白创建与文档编写

从任一档案类别或“其他文档”入口创建，可直接输入标题和正文，无需先上传本地文件。支持与附件共存，保存后能重新打开、继续编辑及阅读。在线讲义/报告可满足原三类对应的材料要求，培训签到仍须上传。

以可视化编写为主要体验，提供以下能力：

- 标题层级、段落、字体/字号、加粗、斜体、下划线、文字颜色、对齐、列表、引用、超链接、撤销与重做。
- 表格的插入、增删行列、常用单元格格式，图片插入、调整尺寸、粘贴文字和截图；保存后重新打开仍然可见。
- 目录、查找和替换、专注编辑、阅读预览。
- 封面、纸张尺寸、页边距、分页、页眉页脚、页码，在阅读、PDF 导出和打印中保持一致的内容与分页逻辑。

文档需要的封面和排版由编辑器提供，不增加模板中心或客户标识套版功能。独立评论区、审批、签章、AI 编写、实时协作不在首版。Markdown 双模式按下列保留规则纳入。

### 可视化与 Markdown 双模式

同一份文档可在可视化和 Markdown 之间双向切换，不拆成两种互不相关的文档。用户已确认以下保留规则，并要求先用实际文档验证：

| 内容 | 切换规则 |
| --- | --- |
| 标题、段落、列表、链接、普通表格和图片 | 两种模式均可编辑，同步回同一份正文。 |
| 页设置、页眉页脚、页码 | 原值保留，在可视化模式中修改，不要求用标准 Markdown 表达。 |
| 合并单元格、浮动图片等复杂内容 | Markdown 中显示只读占位块；切回可视化后保留原对象。 |
| 无法识别、映射或恢复的内容 | 不静默删除，不覆盖原稿；转换失败时保留当前内容并提示原因。 |

首版只提供系统内双模式，正式导出为 PDF/DOCX。Markdown 中的只读复杂块不能因占位缺失或重复而被静默删除、复制；复杂对象在可视化模式修改。

## 11 文档状态自动保存版本与编辑锁

### 状态与归档

状态为“草稿”“已归档”；不设置审批。故障报告直接使用同一状态。

草稿允许边写边存；归档前检查业务必填项及必交材料。归档产生可追溯的档案版本，包含当时业务字段与采用的文档版本清单。

归档后仍允许编辑字段、正文、批注及替换资料。编辑过程先保存待提交草稿，其他阅读者继续看到最后正式保存的内容；正式保存后产生新的归档版本，状态仍为“已归档”，并保留修改前内容和操作者。对外读取不混入编辑者尚未正式提交的草稿。

### 自动保存与版本

- 内容有变化时每 10 秒尝试保存编辑草稿，显示未保存、保存中、已保存或保存失败，以及最后成功保存时间。无变化不重复保存。
- 断网或刷新异常时提供草稿恢复；本机恢复内容按登录账号和文档区分，提示确认后恢复，不静默覆盖服务器新版本。
- 显式保存、附件替换、归档、版本恢复形成正式版本；后台自动保存合并更新同一编辑草稿，不每 10 秒生成一个正式版本。
- 版本历史显示时间、操作者、修改说明及对应资料。正式版本和操作日志首版不自动到期清理。
- 业务字段提供字段差异；在线正文提供内容差异；PDF、附件版本提供并排预览、版本信息与批注差异，不把二进制文件比较承诺为文字级自动合并。
- 恢复历史版本产生一个新的当前版本，保留恢复前版本和恢复操作日志，不删除后续历史。恢复整条档案时恢复对应业务字段及资料版本组合。

### 独占编辑

同一份文档同时只允许一个编辑会话，包括同一账号打开的第二个编辑窗口；其他人可以阅读，编辑入口显示占用者并提示稍后重试。业务字段修改也防止两个会话无提示相互覆盖。

正常保存退出释放编辑锁；心跳每 30 秒更新，连续 5 分钟无心跳视为会话失联，释放后允许他人进入。失去锁的旧页面不能继续覆盖保存，需要重新取得编辑权并核对版本。首版不提供任意抢占仍在线编辑者的入口。

不同文档之间可以分别编辑，不把一个人的文档编辑锁扩展为锁住整个系统。归档、替换或恢复影响到正在编辑的资料时，应先处理占用，不绕过编辑锁修改。

### 删除与恢复

删除和批量删除采用可恢复的删除状态，保留人员日志，恢复后资料及历史仍可定位。归档后也可执行这些操作。首版不在普通界面提供不可恢复的永久清理入口；不因删除记录立即物理销毁所有原件与历史。

## 12 账号范围与人员操作日志

所有已登录账号均能查看、创建、编辑、上传、替换、下载、导出、归档、删除、恢复及查看历史和日志；首版不新增角色、业务组范围或仅本人可见的限制，不把人工录入的讲师/工程师姓名当成登录账号。

继续使用现有登录认证。未登录访问档案、原文件、转换预览、内嵌图片、历史版本和编辑保存接口时需要登录；“所有账号都有权限”不等于匿名公开文件。

日志中的操作者从真实登录会话获取，不能由业务表单中的人名代填。保留当时的账号标识与显示名称，避免账号后来改名导致历史无法辨认。

| 操作 | 记录内容 |
| --- | --- |
| 新建、字段修改 | 操作者、时间、档案、修改字段及修改前后值。 |
| 上传、替换、正文保存、批注修改 | 操作者、时间、文档/文件、前后版本与操作结果。自动保存更新草稿，不要求逐次记录每个输入字符。 |
| 归档、删除、恢复、版本恢复 | 操作者、时间、对象、对应版本及结果。 |
| 下载、导出、打印发起 | 操作者、时间、对象及版本、操作类型；记录的是系统发起的请求，不声称能够证明浏览器或打印机最终完成。 |

普通阅读不逐次生成操作日志。首版不提供修改、删除日志的界面。日志用于回答“谁在何时对哪份资料做了什么”，不是另做一套审批系统。

## 13 下载导出与交付条件

### 已按授权确定的导出范围

| 入口 | 输出 |
| --- | --- |
| 下载上传原件 | 所选文件版本的原始文件，原格式和内容保持不变。 |
| 下载当前附件 | 当前正式上传文件版本；明确区别于历史版本及其派生在线文档。 |
| 导出在线文档 | PDF、DOCX 两种，基于选定的正式文档版本，包含当前表格、图片及排版。 |
| 导出 PDF 批注稿 | 在原 PDF 之外生成带批注的 PDF，可选择是否显示批注；原始 PDF 保持不变。 |
| 导出整条档案 | ZIP，包含档案信息 PDF、当前资料、在线文档的 PDF/DOCX，以及适用的带批注 PDF；默认不打包全部历史版本，不收录未正式提交草稿。 |
| 打印 | 打印档案信息、当前在线文档或可阅读 PDF；PDF 可选择是否显示批注。打印内容与所选版本一致。 |

整条档案导出显示所采用的版本和时间，避免打包过程中内容变化导致混入不同版本。历史资料通过版本入口单独下载。首版不再增加 Excel 列表报表、定制导出模板、电子签署或批量跨档案导出。

### 历史资料与部署

不导入旧系统数据或文件，不做旧入口跳转。新功能从新建档案开始使用。真实开发使用独立预览/测试数据库增加本功能表，不对生产数据库执行迁移。

默认以本项目部署环境内的存储与文档处理能力制定后续方案，不依赖未确认的外部云文档账号；技术方案若需要新增外部服务或费用，再说明其必要性和选择。此处不做组件选型或服务安装。

首版按桌面浏览器编写与阅读设计，优先覆盖 Chrome、Edge。手机编辑、其他浏览器专项兼容及容量性能指标尚未由用户提出，先不增加对应首版验收承诺；如为刚需可补充。

备份与恢复需要覆盖业务信息、在线正文、原件、版本、批注及它们的关联。真实数据量和并发量未知，后续性能验证使用约定样本，不把容量上限视为已完成的压测结果。
