# 档案编辑器技术验证

日期：2026 年 10 月 23 日。范围：独立运行目录中的临时试验，不是正式档案功能验收。业务实现按[开发方案](development-plan.md)继续。

采用候选 Canvas Editor 1.0.5、DOCX 插件 1.0.0、Markdown 插件 0.0.1，均固定版本安装于本实例的 archive-editor-evaluation 目录，未执行依赖安装脚本。直接依赖标示 MIT；30 个安装包的许可证清单包括 MIT、ISC、可选择 MIT 的双许可、MIT AND Zlib、BlueOak 1.0.0。正式交付仍需携带固定版本清单和对应声明。

| 检查 | 结果与实际覆盖 |
| --- | --- |
| TypeScript 4.9 | 最小 Editor/DOCX 类型集成编译通过，使用项目现有 TypeScript；不是全仓新功能类型检查。 |
| Vite 4.5.14 | 临时生产构建通过，8 模块，约 1.25 MB JS、gzip 371 kB；存在大 chunk 提示，正式集成按需加载。 |
| 保存重开 | 页眉、页脚、表格合并、图片及扩展元数据保留。 |
| Word 新实例导入 | 实际导出 DOCX，在空白编辑器导入后保留页眉、页脚、合并单元格和图片。 |
| 原生 Markdown 插件 | 不符合需求：合并单元格信息及节点元数据丢失；不能直接作为正式转换。 |
| 受保护复杂块 | 编辑基础段落后，原始复杂表格和图片结构、页面设置、页眉页脚保持深比较相等；保存重开仍保留。 |
| 无效占位 | 缺失、重复、未知三种情况均拒绝应用；未覆盖当前正文。 |
| 长文 | 70 段中文、72 行跨页表格、浮动图片通过受保护映射；规范化复杂对象与设置保持相等。 |
| PDF | 复用已安装 LibreOffice 26.2.6.3，使用独立配置目录转换真实 DOCX。长文为 9 页；可提取修改后正文、最后一段和最后一行表格，包含文字层、页眉页脚和图片。 |
| Node 序列化可行性 | 从实际快照生成 DOCX，并经 LibreOffice 生成可提取中文的 PDF。临时适配只绕过浏览器下载副作用，不是正式导出 worker。 |
| 浏览器错误 | 上述实际浏览器试验无 pageerror。 |

浏览器画布与 PDF 的长文样本均为 9 页。已查看编辑器、PDF 首页面及 DOCX XML 的页设置、合并字段和页眉页脚引用。此结果不代表任意复杂 Word 的逐像素兼容、所有页面布局、50 MiB 边界或真实并发已验证。

证据保留于该实例的 archive-editor-evaluation：固定依赖锁及许可证清单、baseline-results.json、protected-results.json、long-results.json、pdf-results.json、规范化快照、实际 DOCX/PDF 和截图。试验无业务接口、无业务数据库、无生产资料。

用户已确认：标准以可编辑内容完整、系统内阅读/导出/打印一致为准；复杂 Word 布局先展示转换结果再确认，不要求原 Word 逐页/逐像素一致。仅提供系统内双模式，正式输出 PDF/DOCX，不做独立 .md 上传下载。

正式实现需继续覆盖完整 Markdown 基础语法、复杂对象标识稳定、图片资产、重复文本、断网恢复、租约、版本一致性、导出失败、中文字体、格式边界和真实浏览器链路。任何未执行项不能记为通过。
