# 档案知识接入与资料问答实现记录

## 实施前设计审查

范围：既有档案正式版本自动接入、Markdown 原文和 AI 摘要、授权关键词检索、既有会话输入框 + 模式选择。保持现有根因分析、告警取证和执行链路。无向量与重排模型，无新文档菜单。

模块：`pkg/knowledgebase` 将档案版本提取、持久任务、摘要重试和授权检索放在同一模块；档案继续拥有原件、版本与权限。定期对账发现正式版本，兼容既有数据；不修改档案事务，避免知识处理失败阻塞资料保存。当前最新版本切换后旧索引立即失效，原文解析完成前保持待处理，不用旧内容冒充新内容。

权限：沿用真实规则，档案对有效登录账号开放，正式规程仍受业务组控制。每次搜索/读取重新查询用户和源记录。未新增按客户隔离的 ACL。客户有这种需求时应先扩展档案权限，再复用此处授权入口。

资料问答：服务端指定两项只读工具，不预载 Skill，不发现外部工具源，不沿用操作审批、不传递页面动作。每轮重新读取授权来源；历史只投影用户问题，保留页面原会话。

失败恢复：扫描任务唯一源版本、CAS 租约/提交校验、过期重取；原文与摘要状态分别保存。模型失败不能移除原文。重试有次数与退避；源删除/换版立即从检索排除。图片及无文字 PDF 标为待 OCR。原文不超过 2 MiB；模型摘要仅整理前 14000 字符并注明，整份内容仍分节搜索。

## 验证计划

- 程序行为：正式版本补扫、重复扫描、新版替换、删除与禁用立即拒绝、私有草稿不进入索引、模型失败仍可检索、租约、中文检索、DOCX 表格数字单位。
- 数据库：三方言初始化两次、自动迁移两次、唯一约束、超过 MySQL TEXT 的长文本、中文和 LIKE 字符转义。
- 工程：专项行为测试、make verify、make verify-all、前端生产构建和配套静态资源。
- 运行实例：真实档案上传/正式保存、自动解析和模型整理、中文搜索、资料问答来源引用、无结果、只读工具、原会话切换及草稿保留、页面刷新。
- 人工验收：用户上传脱敏代表资料，对照原文核验抽取、摘要和回答正确性。扫描 OCR、XLSX/PPTX、语义检索不在首版范围。

实际执行结果在交付前补录，计划不代表通过。

## 实现后审查

审查基线为本任务开始时的私有逐文件快照，保留此前处置功能的未提交修改。复核了档案版本/原件访问、知识索引读写、消息路由、原审批恢复、工具实际执行、页面模式状态与来源链接调用链。发现并修正：Canvas 表格嵌套 value 数组需要递归；DOCX 原生 kind 为 docx；源链接历史参数为 version；资料问答不能继承伪装成 user 的工具续接消息，改读原始消息 query；问答最终必须由服务器依据真实 reader 结果复核并追加来源；处理中人工重试应返回 409。

范围限制：关键词检索采用有界数据库候选，未实现大规模全文索引；图片 OCR、直接 TXT/MD 上传与多租户档案 ACL 需后续扩展。原有故障案例到正式规程的审核/发布规则不变。
