# 2026-11-16 用户明确的页面约束

本记录覆盖早先方案与三布局静态原型中冲突的界面建议；尚未进行正式功能开发。

1. 沿用现有“档案管理”上传和维护资料，不新增“文档管理”菜单。上传/正式保存的文档在后台自动整理并进入知识库。
2. 保留“运维知识”入口，客户资料可辅助排障，与案例、预案共用授权检索。
3. 沿用 Nightingale AI 原有双侧栏、欢迎页、会话记录与输入框。仅在输入框底部左侧增加“+”按钮，通过弹出菜单选择运维助手或资料问答；选择资料问答后可显示小标签。
4. 不展示资料范围横条，不要求用户手工选择客户/知识空间。真实查询范围从当前登录账号的权限在服务端推导。
5. 权限由服务端检索/读取工具校验，Agent 根据工具结果答复，不能凭提示词自行授权。授权集合搜索为空回复“未找到相关资料”；指定文档读取返回禁止时回复“没有权限查阅”，不泄露无权标题或内容。来源引用点击后再次校验。
6. 模式切换保留当前会话和可访问的资料引用，不重建互相隔离的资料库。资料问答不提供资源修改和执行权限。
7. 不做语义检索、Embedding 和模型重排。根因分析仍由另一个开发任务实现。

当前档案模块原件访问采用有效登录规则；这些 UI 约束不会自动创造细粒度权限。正式实现必须复用实际账号/文档授权能力，不能仅从客户名称或模型推断虚构权限。本轮静态页面中的无权限与查不到回复均为示例，不代表真实后端鉴权已经完成。

最新原型位于 `frontend/src/pages/opsKnowledge/prototype/knowledge-minimal.html`，对应说明为 `README-minimal.md`。以前的 `knowledge-unified.html` 三布局仅留作历史比较，不是当前建议。
