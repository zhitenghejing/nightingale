# 档案资料知识与问答

上传仍使用档案管理。不创建独立文档菜单，也不改变原有告警根因分析。运维知识新增“资料知识”页，既有正式预案在“处置规程”页。

## 数据与接入

Center 每 5 秒对账档案当前正式文档版本（包括安装前的资料），写入 `knowledge_document_version`；私有编辑草稿不进入知识。`knowledge_document_section` 保存分节 Markdown。源版本唯一约束、CAS 租约、提交前锁与 fence 共同防止重复处理；重启后可回收过期任务。所有资料正文与摘要在数据库中私有保存，不放到 pub 或下载目录。

支持在线文档、DOCX 文字与表格、文字型 PDF。PDF 需 Center 运行环境安装 `pdftotext`（poppler-utils），40 秒提取超时和 2 MiB 文字上限。图片、无文字 PDF 标为待 OCR，未集成 OCR；XLSX/PPTX 及直接 TXT/MD 档案上传不在此版本范围。档案原有上传格式保持不变。

原文先入库即可检索，AI 摘要失败单独退避重试（最多自动尝试 5 次，可人工重试）。无需 Embedding/重排模型，复用 LLM 管理的启用模型。摘要限定前 14000 字符，长资料会注明；全文仍分节检索。摘要不作为正式排障规程自动发布。

最新正式版本切换后旧索引立即退出默认搜索与章节读取；新版本未就绪时保持待处理，不回退成“当前版本”。删除档案/文档、禁用用户时，搜索与读取立即拒绝/排除，不等待后台清理。

## 鉴权与工具

当前档案模块对所有有效登录账号开放，本功能沿用这一真实策略，不新增按客户名称猜测的权限。正式运维预案仍执行业务组权限。所有资料 API 及工具每次重新校验账号与源记录。若后续增加档案 ACL，必须同步 `Store.allowed/visible`，然后补撤权用例。

- `search_knowledge(query)`：当前授权资料中文二字词/英文标识关键词检索，并合并有权读取的正式规程候选。无向量和模型重排，候选最多 1000 节，返回高相关的前 6 条章节（每份文档最多 2 节，过滤通用问句词及弱匹配）；规程候选沿用现有模块限额。大语料需后续专用全文索引。
- `read_knowledge(section_id | procedure_version_id)`：准确读取源版本和章节；重新鉴权，规程需仍有效。

两项知识工具也挂到通用运维会话，客户报告可辅助排障，但不改变根因分析工作流。模式 `knowledge_qa` 使用四项服务端白名单工具：知识搜索、章节读取、对象核对、只读数据查询。不发现外部工具源、不传递页面动作、不重放旧审批、不运行脚本。固定预载编译进程序的 `knowledge-investigation` Skill；不会加载可变的用户 Skill，也不会扩大写操作权限。

### 连续问答与证据

最近六轮保留用户问题；仅对已成功完成的资料问答，将其全部来源重新鉴权、核对版本有效性后，带入最多 3000 字符的上一轮答复帮助理解话题和指代。模型推理、旧工具正文、运维模式答复不直接重放。来源失效、撤权或用户停用时不带入答复。先前答复注明“当时记录”；当前状态必须重新取证。

新事实引用本轮实际工具结果；解释性追问没有调用新工具时，可使用刚重新核验的上一轮证据。新一轮搜索无结果不会借用旧来源伪造命中。证据作用域随消息 Extra JSON 保存，不新增数据库列。最终发布前再次检查来源；正文依据问题选择长度和结构，不强制复盘模板。单轮仍最多 12 次工具调用；达到上限后停止查询，最多追加一次不带工具的模型总结，显式说明未完成项。未执行调用会配对标记，不作为证据；其他非问答流程保持原上限行为。历史报告日期、数据库记录时间、查询时间和底层采样时间必须区分，资料没有记载整改不能推定没有整改。涉及故障原因、复发或现状且读取了文档的答复，会额外使用同一已配置模型进行一次无工具的结论核验（60 秒、4096 token 上限（含模型推理）；截断/过滤结果不发布）；重新读取授权原文，检查缺记录与否定、同期现象与因果、历史状态与实时状态的混淆，核验失败不发布未经核验的结论。该模型核验仍不等于确定性的逐句事实证明。

### 对象关联与实时数据

- `resolve_knowledge_object(ident?, host_ip?, query?)`：限定当前用户监控对象范围。名称搜索只给候选；精确 ident/IP 的唯一匹配给出 `exact_identifier_match`，多个匹配为 `ambiguous`，冲突/无匹配为 `not_found`。同时提供的标识必须同时满足。返回明确的 `historical_mapping=not_established`，当前唯一标识仍不证明历史归属、院区或系统相同。没有新增/猜测 CMDB 绑定。
- `query_knowledge_data(operation, ...)`：复用数据源/设备列表和详情、设备心跳、指标名称、Prometheus 查询、SQL 库表字段及行查询。每次及发布前重新验证账号、设备业务组、数据源可见性和启用状态；配置摘要或设备身份信息变化后旧证据失效，心跳更新时间变化不使身份失效。发现只返回已启用数据源。类型从服务端源配置读取，忽略模型伪造的 datasource_type；不继承页面审批/作用域参数。
- 查询超时 15 秒，Prometheus 窗口最长 24 小时、range 步长 60 秒；单次结果最多 64 KiB，超出后要求收窄，不能把截断当空结果。PromQL 最多四个输入选择器补查 `timestamp(selector)`，明确底层采样时间、求值时间不同；剩余输入、空值或取样失败仍未知。
- SQL 行查询目前开放 MySQL/PostgreSQL，仅允许单条 SELECT/WITH，经共享严格只读校验，并启用数据库只读事务（包括阻止 SELECT 函数内的写入）；其他 SQL 适配器暂仅支持已实现的库表元数据发现；外围查询限制 100 行（默认返回 50 行，达到限制标注可能截断）。PostgreSQL 限制在数据源配置的明确数据库，并复制适配器，避免修改共享连接的数据库选择。必须配置受限的数据库只读账号；本功能不自动授予或推断数据库表/行权限。先发现库表字段，业务口径来自文档或用户确认。未接入数据库时明确缺口。
- 实时查询来源保存操作、授权对象、查询和时间。最终引用区展示查询时间，不能用“本次核对”证明数据新鲜、同对象关联正确或结论已证实。没有实时监测项，不能用普通主机指标代替 F5 HA/MAC 漂移核查。


## HTTP

统一 `/api/n9e/knowledge-documents`，使用现有登录认证，响应 `{dat,err}`。

| 方法与路径 | 作用 |
| --- | --- |
| GET `/` | 当前源版本处理状态，最多 500 项 |
| GET `/search?q=...` | 关键词检索，query 最多 1000 字节 |
| GET `/sections/:id` | 授权章节全文、源版本与链接 |
| GET `/:id` | 当前可访问知识版本 Markdown 和摘要 |
| POST `/:id/retry` | 重试未完成解析/摘要，处理中返回 409 |

会话 query 新增 `mode: ops | knowledge_qa`；省略兼容原运维会话，非法值返回 400。字段跟随消息 JSON 持久化，不增加会话表列。没有新增 edge/alert 读取或 CenterApi 契约。

三种方言 SQL 见 `doc/sql/knowledge-documents.*.sql`，可 `go run ./cmd/knowledge-schema` 重建；初始化和迁移脚本同步维护。

## 重复验收

在隔离预览上配置可用模型，然后生成测试资料：

```bash
python3 -B scripts/knowledge_fixtures.py /path/to/private/fixtures
```

设置 `N9E_E2E_BASE_URL`、`N9E_E2E_BUILD_ID`、`N9E_E2E_CREDENTIALS_FILE`、`N9E_KNOWLEDGE_FIXTURE_DIR`、`N9E_KNOWLEDGE_E2E_OUTPUT`；浏览器安装在非默认位置时设置 `N9E_E2E_CHROME`，执行 `node scripts/knowledge_e2e.mjs`。脚本要求 development 身份与 build ID 一致，创建明确标注的隔离资料，校验真实模型、只读、空结果、换版、删除。`KB_RESUME=1` 只复用输出目录记录的本脚本档案，不重新上传。不得指向稳定/生产环境。脚本不替代客户资料正确性和人的体验验收。

## XLSX 资料

档案上传 `.xlsx` 后仍保存原件、编辑租约和不可变正式版本。后台扫描同一资料链路，生成按工作表/单元格坐标组织的 Markdown 章节及 `knowledge_document_workbook` 结构化快照，事务内随索引一起保存。摘要重试不删除确定性原文。替换、删除、停用账号后，旧索引立即失去当前可见性；历史原件在档案阅读权限内保留。

`query_knowledge_workbook` 同时提供给通用会话及资料问答，按服务器当前登录账号执行。先通过 `search_knowledge` 的 `documents[].version_id` 定位知识版本，再 `operation=sheets` 查看工作表，`read` 读取指定 `range`（如 `A1:F100`），或 `count/sum` 计算指定范围内全部非空行。`sum` 要求 `column`；筛选使用 `filter_column/filter_operator(eq,contains,gt,lt)/filter_value`。分页只限制返回行，不限制统计扫描；`limit` 1–100，默认 50。结果包括 `scanned_rows/matched_rows/numeric_cells/complete/issues/has_more`。输出最多 64 KB，单行超过 48 KB 时要求缩小列范围，不能静默截断。无数据不能解释为正常。

数值使用保存的原始数值精确累加，以 12 位小数展示；计数覆盖非空数据行，不自动剔除表头、合计或隐藏行。缺值、错误或无缓存公式使相关统计 `complete=false`；返回的 sum 是可计算部分，不能称为完整总数。百分比按原始比例，跨单位不能混算。合并值仅在左上格，不自动向下填充。文本型数字保留文本语义（例如 0007），不擅自转数字。日期按工作簿样式展示。

工具返回服务器创建的证据回执（知识版本、摘要指纹、文件 Vn、工作表范围和来源链接）。资料问答模式发布回答与历史对话复用前重新核对源版本和账号；不把报告内容当作已验证处置规程或实时设备状态。已有环境关联器只提出候选关联，不写入设备/CMDB。

限制：仅普通、未加密 `.xlsx`；`.xls/.xlsm` 要求另存为无宏 `.xlsx`。不在线编辑、不执行公式或宏、不访问外部链接；图片、图表、批注及打印排版不参与知识提取。读取并发 2、原件 50 MiB、ZIP 总解压 128 MiB/单项 32 MiB/条目 3000、工作表 32、实际范围 100000 行/256 列、单元格 XML 条目 100000（含空样式格）、非空单元格 50000、展开单元格文本 8 MiB、隐藏行列/合并元数据合计 1024 项、Markdown 2 MiB、结构化索引 16 MiB。超限拒绝并说明拆分要求，禁止伪装为已完整整理。
