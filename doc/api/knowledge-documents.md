# 档案资料知识与问答

当前范围（2026-11-25）：闭环资料接入、知识整理、检索问答及资料变更后的维护。故障处置、根因分析、故障经验自动沉淀暂不推进；“告警处置”菜单及页面入口移除，旧链接转到资料知识，保留历史数据与兼容接口。

上传仍使用档案管理。不创建独立文档菜单，也不改变原有告警根因分析。运维知识新增“资料知识”页，既有正式预案在“处置规程”页。

## 数据与接入

Center 每 5 秒对账档案当前正式文档版本（包括安装前的资料），写入 `knowledge_document_version`；私有编辑草稿不进入知识。`knowledge_document_section` 保存分节 Markdown，`knowledge_document_term` 保存可重建的哈希词项倒排记录，`knowledge_document_derivation` 保存逐节派生知识、原文摘要指纹、生成配方、模型标识和重试状态。源版本唯一约束、CAS 租约、提交前锁与 fence 共同防止重复处理；重启后可回收过期任务。所有资料正文与摘要在数据库中私有保存，不放到 pub 或下载目录。

支持在线文档、DOCX 文字与表格、文字型 PDF。PDF 需 Center 运行环境安装 `pdftotext`（poppler-utils），40 秒提取超时和 2 MiB 文字上限。图片、无文字 PDF 标为待 OCR，未集成 OCR；支持 XLSX（详见文末），PPTX 及直接 TXT/MD 档案上传不在此版本范围。档案原有上传格式保持不变。

原文先入库即可检索，AI 摘要失败单独退避重试（最多自动尝试 5 次，可人工重试）。无需 Embedding/重排模型，复用 LLM 管理的启用模型。按原文章节分批整理，新建索引单节模型输入最多6000字符（旧索引按原有章节处理，原文不截断），完成一节即保存，最终摘要确定性拼接各节事实、术语和有依据的FAQ候选。正文始终是回答事实的权威来源；派生知识不替代原文。界面显示已整理/总章节覆盖，失败仅重试未完成章节。旧版前14000字符摘要被新配方替换。摘要不作为正式排障规程自动发布。

最新正式版本切换后旧索引立即退出默认搜索与章节读取；新版本未就绪时保持待处理，不回退成“当前版本”。删除档案/文档、禁用用户时，搜索与读取立即拒绝/排除，不等待后台清理。

## 鉴权与工具

当前档案模块对所有有效登录账号开放，本功能沿用这一真实策略，不新增按客户名称猜测的权限。正式运维预案仍执行业务组权限。所有资料 API 及工具每次重新校验账号与源记录。若后续增加档案 ACL，必须同步 `Store.allowed/visible`，然后补撤权用例。

- `search_knowledge(query)`：当前授权资料中文二字词/英文标识关键词检索，并合并有权读取的正式规程候选。无向量和模型重排，使用中文二字词、英文标识及精确设备/IP词项的倒排记录，在数据库中先评分再取最多1000节候选，返回高相关前6节（一般每文档最多2节；显式限定文档/版本时最多6节，过滤通用问句词及弱匹配）；规程候选沿用现有模块限额。三种数据库共用持久倒排表，不再对已建索引正文进行LIKE扫描；升级未完成的旧资料及改名待同步资料保留临时兼容路径。索引可由原文重建，不需要Embedding或重排模型。
- `read_knowledge(section_id | procedure_version_id)`：准确读取源版本和章节；重新鉴权，规程需仍有效。

两项知识工具也挂到通用运维会话，客户报告可辅助排障，但不改变根因分析工作流。模式 `knowledge_qa` 使用服务端只读白名单：知识搜索、章节读取、Excel目录/范围读取/计数/求和、环境关联、对象核对与数据查询。不发现外部工具源、不传递页面动作、不重放旧审批、不运行脚本。这只是旧客户端显式 `knowledge_qa` 的兼容路径，不用于普通统一入口。主 Agent 可以从授权目录加载可组合的 `knowledge-investigation` 等 Skill。

### 连续问答与证据

最近六轮保留用户问题；仅对已成功完成的资料问答，将其全部来源重新鉴权、核对版本有效性后，带入最多 3000 字符的上一轮答复帮助理解话题和指代。模型推理、旧工具正文、运维模式答复不直接重放。来源失效、撤权或用户停用时不带入答复。先前答复注明“当时记录”；当前状态必须重新取证。

新事实引用本轮实际工具结果；解释性追问没有调用新工具时，可使用刚重新核验的上一轮证据。新一轮搜索无结果不会借用旧来源伪造命中。证据作用域随消息 Extra JSON 保存，不新增数据库列。最终发布前再次检查来源；正文依据问题选择长度和结构，不强制复盘模板。单轮仍最多 12 次工具调用；达到上限后停止查询，最多追加一次不带工具的模型总结，显式说明未完成项。未执行调用会配对标记，不作为证据；其他非问答流程保持原上限行为。历史报告日期、数据库记录时间、查询时间和底层采样时间必须区分，资料没有记载整改不能推定没有整改。涉及故障原因、复发或现状且读取了文档的答复，会额外使用同一已配置模型进行一次无工具的结论核验（200 秒、4096 token 回答上限（是否包含推理取决于供应商接口）；截断/过滤结果不发布）；重新读取授权原文，检查缺记录与否定、同期现象与因果、历史状态与实时状态的混淆，核验失败不发布未经核验的结论。该模型核验仍不等于确定性的逐句事实证明。

### 对象关联与实时数据

- `resolve_knowledge_object(ident?, host_ip?, query?)`：限定当前用户监控对象范围。名称搜索只给候选；精确 ident/IP 的唯一匹配给出 `exact_identifier_match`，多个匹配为 `ambiguous`，冲突/无匹配为 `not_found`。同时提供的标识必须同时满足。返回明确的 `historical_mapping=not_established`，当前唯一标识仍不证明历史归属、院区或系统相同。没有新增/猜测 CMDB 绑定。
- `query_knowledge_data(operation, ...)`：复用数据源/设备列表和详情、设备心跳、指标名称、Prometheus 查询、SQL 库表字段及行查询。每次及发布前重新验证账号、设备业务组、数据源可见性和启用状态；配置摘要或设备身份信息变化后旧证据失效，心跳更新时间变化不使身份失效。发现只返回已启用数据源。类型从服务端源配置读取，忽略模型伪造的 datasource_type；不继承页面审批/作用域参数。
- 设备数量、字段分布及已接入信息以平台当前设备库为主：独立工具 `target_statistics(query, group_by=none|os|agent_version|engine_name)`（旧 `query_knowledge_data(operation=target_statistics,...)` 兼容） 在当前账号可读Target集合上全量SQL聚合，按ident计数，不按IP去重，不受列表分页影响。query必须显式提供，保留用户完整筛选标识/前缀，只有查询全部设备才传空字符串。独立工具仅接受query/group_by，防止混入SQL或监控时间窗口参数。独立工具的group_by同样必填：none表示只查总数，其他值为明确分组字段；兼容入口分布使用group_by；target_statistics中table仅兼容os/agent_version/engine_name这三个明确维度的别名，并在normalized_arguments回执注明，冲突维度、其他表名及SQL参数拒绝；省略时仅返回总数，不能推断其他字段的空值数量。总数完整性与分组截断分别返回；Target库不等于全部CMDB资产，库中记录不证明设备健康。发布及历史复用前重新校验账号和业务组权限范围。Excel只回答明确指定台账中的历史记录，不替代平台当前设备统计。
- 查询超时 15 秒，Prometheus 窗口最长 24 小时、range 步长 60 秒；单次结果最多 64 KiB，超出后要求收窄，不能把截断当空结果。PromQL 最多四个输入选择器补查 `timestamp(selector)`，明确底层采样时间、求值时间不同；剩余输入、空值或取样失败仍未知。
- SQL 行查询目前开放 MySQL/PostgreSQL，仅允许单条 SELECT/WITH，经共享严格只读校验，并启用数据库只读事务（包括阻止 SELECT 函数内的写入）；其他 SQL 适配器暂仅支持已实现的库表元数据发现；外围查询限制 100 行（默认返回 50 行，达到限制标注可能截断）。PostgreSQL 限制在数据源配置的明确数据库，并复制适配器，避免修改共享连接的数据库选择。必须配置受限的数据库只读账号；本功能不自动授予或推断数据库表/行权限。先发现库表字段，业务口径来自文档或用户确认。未接入数据库时明确缺口。
- 实时查询来源保存操作、授权对象、查询和时间。最终引用区展示查询时间，不能用“本次核对”证明数据新鲜、同对象关联正确或结论已证实。没有实时监测项，不能用普通主机指标代替 F5 HA/MAC 漂移核查。


## HTTP

统一 `/api/n9e/knowledge-documents`，使用现有登录认证，响应 `{dat,err}`。

| 方法与路径 | 作用 |
| --- | --- |
| GET `/` | 当前源版本处理状态，最多 500 项 |
| GET `/search?q=...` | 关键词检索，query 最多 1000 字节 |
| GET `/sections/:id` | 授权章节全文、源版本与链接 |
| GET `/:id` | 当前可访问知识版本 Markdown 和摘要 |
| POST `/:id/retry` | 按mode=unfinished重试未完成章节，mode=regenerate重新生成AI整理；省略兼容旧入口，处理中返回409 |

会话 query 支持 `mode: auto | ops | knowledge_qa`；省略或 auto 规范为 auto，走通用主 Agent；显式旧模式兼容，非法值返回400。字段跟随消息 JSON 持久化，不增加会话表列。没有新增 edge/alert 读取或 CenterApi 契约。

三种方言 SQL 见 `doc/sql/knowledge-documents.*.sql`，可 `go run ./cmd/knowledge-schema` 重建；初始化和迁移脚本同步维护。

## 重复验收

在隔离预览上配置可用模型，然后生成测试资料：

```bash
python3 -B scripts/knowledge_fixtures.py /path/to/private/fixtures
```

设置 `N9E_E2E_BASE_URL`、`N9E_E2E_BUILD_ID`、`N9E_E2E_CREDENTIALS_FILE`、`N9E_KNOWLEDGE_FIXTURE_DIR`、`N9E_KNOWLEDGE_E2E_OUTPUT`；浏览器安装在非默认位置时设置 `N9E_E2E_CHROME`，执行 `node scripts/knowledge_e2e.mjs`。脚本要求 development 身份与 build ID 一致，创建明确标注的隔离资料，校验真实模型、只读、空结果、换版、删除。`KB_RESUME=1` 只复用输出目录记录的本脚本档案，不重新上传。不得指向稳定/生产环境。脚本不替代客户资料正确性和人的体验验收。

## XLSX 资料

档案上传 `.xlsx` 后仍保存原件、编辑租约和不可变正式版本。后台扫描同一资料链路，生成按工作表/单元格坐标组织的 Markdown 章节及 `knowledge_document_workbook` 结构化快照，事务内随索引一起保存。摘要重试不删除确定性原文。替换、删除、停用账号后，旧索引立即失去当前可见性；历史原件在档案阅读权限内保留。

`query_knowledge_workbook` 同时提供给通用会话及资料问答，按服务器当前登录账号执行。先通过 `search_knowledge` 的 `documents[].version_id` 定位知识版本，再 `operation=sheets` 查看工作表，`read` 读取指定 `range`（如 `A1:F100`），或 `count/sum` 计算指定范围内全部非空行。`sum` 要求 `column`；筛选使用 `filter_column/filter_operator(eq,contains,gt,lt)/filter_value`。分页只限制返回行，不限制统计扫描；`limit` 1–100，默认 50。结果包括 `scanned_rows/matched_rows/numeric_cells/complete/issues/has_more`。输出最多 64 KB，单行超过 48 KB 时要求缩小列范围，不能静默截断。无数据不能解释为正常。

数值使用保存的原始数值精确累加，以 12 位小数展示；计数覆盖非空数据行，不自动剔除表头、合计或隐藏行。缺值、错误或无缓存公式使相关统计 `complete=false`；返回的 sum 是可计算部分，不能称为完整总数。百分比按原始比例，跨单位不能混算。合并值仅在左上格，不自动向下填充。文本型数字保留文本语义（例如 0007），不擅自转数字。日期按工作簿样式展示。

工具返回服务器创建的证据回执（知识版本、摘要指纹、文件 Vn、工作表范围和来源链接）。资料问答模式发布回答与历史对话复用前重新核对源版本和账号；不把报告内容当作已验证处置规程或实时设备状态。已有环境关联器只提出候选关联，不写入设备/CMDB。

限制：仅普通、未加密 `.xlsx`；`.xls/.xlsm` 要求另存为无宏 `.xlsx`。不在线编辑、不执行公式或宏、不访问外部链接；图片、图表、批注及打印排版不参与知识提取。读取并发 2、原件 50 MiB、ZIP 总解压 128 MiB/单项 32 MiB/条目 3000、工作表 32、实际范围 100000 行/256 列、单元格 XML 条目 100000（含空样式格）、非空单元格 50000、展开单元格文本 8 MiB、隐藏行列/合并元数据合计 1024 项、Markdown 2 MiB、结构化索引 16 MiB。超限拒绝并说明拆分要求，禁止伪装为已完整整理。


## Qwen 回归后的问答执行契约

下述生成式复核与12次工具额度仅适用于旧客户端显式 knowledge_qa；普通 auto 使用后文的统一主 Agent，不增加第二次模型改写。搜索、读取与工作簿约束适用于两者。

- 搜索接受可选 `document_title` 与知识 `version_id`，先限定源再查询章节；标题按完整文件名匹配（允许档案显示前缀），缺省或整数0表示不限定版本；正版本ID不会在无匹配时扩大范围。设备标识在 SQL 候选上限之前参与优先排序，V2/A12等歧义词不会硬性排除其他匹配。无匹配不回退其他资料。原 `Search` 入口保留。
- `search_knowledge.documents` 仅为候选定位元数据；`read_documents` 是同次调用中经正式读取接口重新鉴权取得的最多3个章节、合计12000字符。截断明确标注，不能据此作全文排除。只有正式读取部分计入来源证据。
- 资料问答优先提供 `list_workbook_sheets(version_id)`、`read_workbook_range(version_id,sheet,range,offset?,limit?,filter_*)`、`count_workbook_rows(version_id,sheet,range,filter_*)`、`sum_workbook_column(version_id,sheet,range,column,filter_*)`。旧 `query_knowledge_workbook` 为既有通用工作流保留。所有入口共享读取、限额和权限检查；不完整筛选参数会拒绝，不会退化为全量统计。
- 范围读取返回与范围相交的 `merged_ranges`、锚点和值，不向空白格填值，也不改变计数口径。静态Excel统计不会因“是否监控”列名触发实时排查。
- 单文件、明确工作表与单列范围的简单等值计数/无筛选求和，可由服务端根据本轮回执重新读取当前授权工作簿计算后发布。输出只描述计算和完整性；模型草稿不作事实来源。复杂条件、跨表比较和当前状态仍经语义核验。附带的无关计数不会强制资产事实问答进入统计核验。
- 生成式结论核验单次总预算200秒、4096 token，使用独立缓存客户端设置相同的响应头等待上限，不修改主Agent客户端预算，不重试，异常不放出未经核验的结论。对已确认支持原生参数的 SiliconFlow Qwen3 接口，单次核验另设1024 token思考预算；主Agent保持原模型配置，其他接口不发送此厂商字段，用户配置的更低预算或关闭思考仍被尊重。消息内部Extra保存 `knowledge_review`：状态、模型配置标识、耗时、输入字节、可见输出字符、结束原因及用量。不保存凭据、原始服务错误正文或隐藏推理。超时、限流、截断、空输出分别记录。
- 只读问答中相同规范化参数失败两次后不再执行同一调用；写操作幂等规则与其他工作流不变。
- 固定Skill按资料事实、统计、环境关系、实时状态选择证据。不同快照冲突、同IP多SN、缺少Target或样本、用途与正式业务归属分别保留证据边界。规则不包含客户测试答案。

- 无原生工具调用且可见正文为空或仅为已知协议标签时，只读问答允许一次协议修复。修复提示只进入本次请求投影，真实异常响应和实际工具配对仍保留；沿用原截止时间、迭代和12次工具额度。再次异常、额度耗尽或最终正文仍无有效内容时明确未完成，不附引用伪装成功。消息Extra记录协议修复次数。
- 确定性统计拒绝否定、近似文件名/工作表名、来源不唯一和多条件问法；仅使用重新授权且指纹一致的源。指定求和范围中的整行缺失也标记统计不完整，不将其当作零。

## 资料维护与恢复

原文解析/对账与模型整理使用独立后台循环；慢摘要不阻塞新资料原文入库。每份当前正式版本以数据库租约控制提交，解析和整理提交前核对源当前版本；模型返回期间资料换版、删除或租约丢失不得发布旧派生产物。

解析器版本升级会在租约空闲时将旧派生内容撤出检索并重新排队，从不可变原件重建正文、章节和工作簿；同轮至多处理10份，不抢占活跃租约。索引升级、标题修改由后台对账自动重建，单轮最多10份，记录后台失败日志。改名后读取立即采用源标题；未重建标题词项前仍可检索新名称。模型配置标识或生成配方改变使旧整理退出当前详情，后台逐节重新生成；每节保存输入摘要指纹、模型与配方。换版后的全部派生产物继承旧源失效，默认检索与历史上下文复用均重新检查，不把旧知识当当前依据。历史原件由档案版本页面追溯。

未完成资料的重新处理仅重试未完成解析/章节，保留成功章节，重置失败节预算；全部整理完成后，操作变为“重新生成整理”，撤回当前AI草稿并重新生成全部章节，保留原文、索引和正式来源版本；活跃租约返回409。资料阅读抽屉定期刷新，换版/删除后关闭失效内容。纯资料变更不自动创建设备、关系、故障案例或正式处置规程。

仍保留的格式边界：扫描件/图片待OCR，复杂图表不推断；未配置的格式适配和客户隔离ACL不由模型补足。模型输出的引用与语义正确性通过真实模型评测持续核对，不宣称逐句确定性证明。

## 单文件问答与结论边界

资料问答中，用户用一组书名号明确指定一份资料时，服务端从本轮真实问题绑定标题范围，覆盖模型自行提供的搜索标题。章节读取、工作簿读取及历史答复复用均检查同一范围，不能用其他文件或旧对话来源扩大回答；多份明确标题仍允许比较，不强制合并。该限制不改变账号权限，也不把历史台账当当前设备库。

长序列号（至少两个字母和四个数字）及完整IP作为精确检索约束；无匹配不返回仅命中“编码”等通用词的噪声章节。V2/A12等短版本或单元格标记保持软匹配。精确标识同时从本轮真实用户问题绑定到检索、读取及历史复用，模型改用前缀、同义词或其他编号不能放宽该约束；没有匹配时不附加无关资料作为来源。

涉及确认、证明、断定等判断，或模型草稿自行加入推论时进入结论核验。图示高度、名称、位置、连线只能证明图中如何标注，不能升格为已核实的实物尺寸、身份、配置或拓扑；普通术语解释不能替代实际核验。模型核验仍是质量门禁，不是形式化的逐句事实证明。

后台对账只读取版本与索引元数据，不周期搬运所有正文；检测到已就绪资料缺失章节时重新排队解析，不让坏任务持续阻塞整理队列。


## 统一问答入口与联合取证

输入框不显示模式选择及“按问题自动查询资料与平台数据”提示语。普通消息省略 `mode`，服务端规范为 `auto`，始终交给 `general_chat` 主 Agent 理解、规划和调用；不按问句关键词分配“运维或资料”的排他路线。显式 Skill、表单回传仍由主 Agent 处理，既有工具权限、缺参表单、写操作审批及工具源授权保留。旧客户端显式 `ops` / `knowledge_qa` 兼容；后者才使用旧只读白名单与复核流程。

主 Agent 同时具有现有运维查询、资料搜索/读取、工作簿读取/统计、平台数据和环境工具，并保留授权 Skill 目录、load_skill、渐进工具披露及配置的工具源。Skill 可以组合；knowledge-investigation 的取证约束仅作用于资料事实核对，不全局禁止用户明确要求的其他操作。主模型按子问题决定查询顺序、观察后修订计划；工具可用不要求每次全部调用。

资产身份、厂商、型号、登记位置按完整序列号调用现有 `query_knowledge_data(operation=asset_lookup, serial="完整序列号")`：使用 CMDB 本身的资产读取ACL，先精确谓词再读取，不经过通用环境扫描上限，不借用 Target 业务组权限。仅返回白名单资产字段、修订、更新时间与机柜绑定状态，不返回任意 payload 或口令。没有规范机柜绑定时，台账位置明确标记为登记信息。发布和历史重放时检查账号、权限与资产指纹；记录变更、删除或“未找到”后新增会使旧回执失效。CMDB更新时间是记录时间，不是现场核查时间。

已接入设备数量/分布仍用 Target 的 `target_statistics` 全范围查库；实时状态需要对象匹配和新采样。附件/Excel是有版本和日期的历史事实，不能替代当前资产主记录或实时状态。比较时并列对象、时间、范围、冲突值和未知项，不能凭上传日期自动覆盖登记信息。独立编号资料检索保留完整编号，长纯数字序列号也参与精确词项匹配；不把目录自动读取当正文事实。

内置工具在处理器默认值之前校验已提供参数的 JSON 类型；数字标识必须是字符串，前导零保留，错误类型不得变成空过滤。缺少参数仍交既有表单/审批处理器处理。相同只读失败调用最多执行两次，随后要求改正参数或说明缺口。

实际读到的来源回执在发布前再次鉴权；搜索或读取中已返回正文的正式规程也记录版本回执，复验业务组权限、撤回与复审期限并保留历史依赖，发布复验沿用请求取消上下文；取证后的正文先缓冲，检查完成后再发送及结束流，引用按资料版本去重，只保留本答案使用的原文及必要查库来源，不附加未使用目录。主 Agent 的措辞不再经过额外模型重写。普通auto问答保留模型既有思考配置；只对有可靠回执的资料/资产取证判断是否新增来源、记录和单元格，连续两轮无进展时由同一主模型无工具收尾。原请求截止前预留120秒作答，用户取消仍立即生效；运维操作、Skill加载及未纳入的工具维持自身流程。常用原生监控/数据库读工具保留原返回格式，附带服务端来源回执；其他运维工具继续其原契约。历史答复经来源重验后用于指代理解，上一轮实时查询不能作为本轮新事实。该机制约束可追溯来源和权限，事实口径及语义正确性仍需模型用例与人工验收。

统一入口修复保留既有 knowledge-investigation Skill，并新增独立 target_statistics Tool 以明确必填筛选和统计维度；asset_lookup 是 query_knowledge_data 内部操作，不单独计作 Tool。相对分支创建时 main（2ba46536），当前源码共新增1个 Skill、20个 Tool，其中9个为早期处置闭环专用工具，相关注册与后端实现保留，页面入口已移除。

精确设备标识的Excel搜索同时返回matched_records：授权工作簿的完整匹配行、匹配单元格、原始前3行上下文（不自动推断表头）、合并/缺值状态及可直接复制的版本引用。主Agent可直接对照，不再从章节片段猜测筛选列。失败轮保存已完成工具调用、参数、来源回执、耗时及失败类型，不保存隐藏推理；普通来源对话保留最近六轮经来源重验的可见上下文。

候选documents在工具响应中仅提供标题、定位ID、版本和章节元数据，不再夹带可误作事实的正文摘录；事实来自read_documents与matched_records。普通对照只覆盖本轮必要来源，非穷尽检索不概括“所有报告”；型号尾缀、客户院区和时间缺少明确映射时保留原始差异。
