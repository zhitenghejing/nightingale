# 1.0平台标签映射与告警规则控频

实施基线：3982dbdc。范围为通知规则「1 通知配置」中的专用渠道，2基础配置、3工作流与其执行顺序不变。不开启真实媒介、不访问1.0生产接口。

## 设计

- 新映射版本 `mapping_version=event_labels_v1`；deviceType/deviceName读取手填事件标签键。companyId保留固定文本/标签二选一，level保留事件Severity与显式level_map，所有时间、事件类型、标题、签名规则不变。
- `device_tags_source=event_labels`，`device_tags_labels`为有序JSON文本，每项含 `label`（标签键）、`required`（明确布尔值）。按序拼接完整值，用ASCII逗号，不加方括号、不拆值、不去重。可选标签缺失/空值省略并在任务详情展示；歧义值仍报错，全部为空阻止发送。
- 已有CMDB、固定值、整段附加标签配置保留读取和旧编辑能力，明确切换后才清理停用映射。新标签键留空，不猜测客户实际标签。
- 原始持久事件是映射来源。规则附加标签已合并，可读取；通知规则工作流临时改变的副本标签不参与映射。工作流放行/丢弃、屏蔽、过滤、恢复开关继续生效。
- 故障通知次数与重复间隔由告警规则统一控制（最大次数0不限、1含首次、3含首次及两次提醒）。渠道不额外限制每轮故障次数，也不对正常提醒要求人工审核。旧repeat_policy参数仅保留快照兼容，不再参与故障发送决策，新配置使用兼容值all_dispatches。
- 复用stream租约保持有序，同次派发按目的端+DispatchID去重；不同DispatchID的正常提醒可以发送。前序已尝试结果不明时暂停后续提醒和恢复，人工核对后再继续。恢复的重复防护保留，恢复通知不占故障最大次数。不改通用渠道或引擎控频。历史已抑制/取消任务不自动重新排队或补发。
- 人工授权重发同一任务沿用现有核对、版本和签名保护；它是明确操作，不是自动重复提醒。因此不宣称所有情况下绝对只有一次网络请求。
- 恢复在领取时引用已受理故障的归属、设备、标签、等级、problemTime和签名；不要求恢复事件重新携带全部业务标签。未投递故障不补造，已尝试结果不明时保持阻塞。
- 不新增表/列：映射存入已有规则参数，来源和省略信息由不可变任务快照重现；同次派发并发互斥由现有数据库stream租约与尝试记录实现。不会改变旧任务快照和历史签名。
- 映射预览是管理员只读检查：输入现有历史事件ID和草稿参数，仅构造脱敏报文，不登记任务、不读取密钥、不执行工作流、不访问接收端。它不能代替实际派发或证明通知规则命中。

## 验证边界

沿已授权接口验证：Build字段构造、RegisterDispatch持久登记、Worker.Step本地模拟投递、Get只读详情、通知规则表单保存/回显与实际预览界面。使用隔离数据库、合成事件、httptest服务；不使用真实密钥或真实目的端做网络测试。

可靠性边界仍包括首次任务登记前的崩溃窗口、异常生命周期身份、人工重发的接收端重复风险；不宣称绝不丢失或能够证明人员通知完成。正常恢复只覆盖引擎判定的同一轮次，不跨旧轮次补恢复。

最终检查、预览构建和页面验收结果随交付记录提供；SQLite通过不代表其他数据库或部署模式通过。
