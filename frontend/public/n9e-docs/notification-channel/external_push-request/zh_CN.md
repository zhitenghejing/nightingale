# 1.0平台推送

## 当前字段映射（事件标签版）

本次调整只涉及通知规则的「1 通知配置」专用渠道参数。「2 基础配置」「3 事件处理工作流」和筛选、屏蔽、恢复开关保持原行为。

| JSON字段 | 取值方式与规则 |
| --- | --- |
| alarmType | 事件状态自动决定：故障problem、恢复ok。 |
| companyId | 原规则不变：固定文本或手填事件标签键，二选一且非空。 |
| deviceType | 手填事件标签键，取该键的完整值，必须唯一且非空。 |
| deviceName | 手填事件标签键；保留IP、端口、括号等完整值。 |
| problemTime | 本轮FirstTriggerTime，按媒介时区格式化；恢复保留已受理故障值。 |
| recoveryTime | 故障为空字符串；恢复取RecoverTime，不是HTTP发送时间。 |
| triggerName | 原始事件RuleName；恢复继承对应故障内容。 |
| level | 事件Severity与显式等级映射，来源仍是告警规则等级，不读取等级标签。 |
| deviceTags | 有序配置多个标签键，完整值用英文逗号拼接为一个字符串。 |
| sign | center独立密钥文件生成，页面不填写或回传密码。 |

例如来源model、business分别为R650、HIS，deviceTags发送 `"R650,HIS"`，不加方括号，不含标签键。每项可设必填或可选；可选项不存在或值为空时省略，并在草稿预览及任务详情显示原因。全部为空或任一来源存在不同非空值时阻止发送。不拆分值内的逗号，不按值去重。

标签来源是已入库事件标签，包含已合并的告警规则附加标签；填写标签键，不是值或{变量}模板。工作流临时改写的通知副本标签不作为映射输入。新配置不猜测客户标签键。既有CMDB、固定值或整段附加标签映射保留；只有明确点击「切换为事件标签映射」才清理停用来源，客户标识与等级关系保留。

「检查映射（不发送）」由管理员选择已有历史事件ID校验草稿，不登记任务、不执行工作流、不读取密钥或访问接收端；不能证明实际通知规则命中。恢复业务字段在worker领取时引用已受理或人工确认的对应故障。

故障次数与重复间隔由告警规则统一控制：最大次数0不限，1为首次一次，3为首次加两次提醒。本渠道不再设每轮一次或人工审核提醒的独立限制；旧repeat_policy仅保留兼容，不影响故障次数。同次派发按目的端与DispatchID去重，不使用sign去重。恢复不占故障次数，重复恢复保护仍保留。结果不明时暂停后续提醒和恢复，核对后再继续，不盲目重投。历史已抑制/取消任务不自动补发。没有实际投递的故障不补造；恢复被本地开关过滤时1.0可能保留未恢复故障。

以下CMDB说明仅适用于未明确切换的既有配置。

系统默认在通知媒介列表保存一条“1.0平台推送”，初始关闭，可被既有通知规则选择。内部external_push标识不变，已存在的用户自建媒介名称和通知规则不被批量改写；管理员保存的配置在重启时保留。

真实接口模式固定使用 `https://admin.ztservice.cn/messageWarn!acceptWarn.act`，POST，Content-Type为 `application/x-www-form-urlencoded; charset=UTF-8`。表单字段json承载一个完整JSON对象，结构化序列化后由HTTP客户端编码，不是直接发送application/json，也不把告警放入URL。默认10秒超时，不自动重试或跟随重定向。

成功接收后1.0可能真实触发账号、短信及电话通知。仅启用媒介且命中已启用的通知规则时才登记发送；本轮只准备配置，保持关闭，等待下一步指令。接口报告接收成功与后续人员通知分别验收。

## 业务字段

- companyId在通知规则填写固定值或显式告警标签。本次客户值只存实例测试规则，不作为软件默认值。
- deviceType/deviceName可选择CMDB.type及CMDB.hostname。必须明确告警标签与CMDB主机名/业务IP/带外IP的精确对应；不会自动删除端口、猜测关联或选择第一条。未匹配、多个匹配、设备字段缺失时阻止发送。原固定类型/告警标签来源保留兼容。
- deviceTags本次选择“CMDB：型号 + 所属业务”，从同一匹配资产读取model和business，按 `"['R650', 'HIS']"` 作为JSON字符串发送，型号在前、所属业务在后。任一字段为空时阻止发送。保留原附加标签、固定字符串或指定标签方式以兼容已有配置。
- “查找CMDB的告警标签键”不直接对应任何输出JSON字段。例如CMDB匹配字段选hostname、此处填ident，就用告警标签ident的值查找CMDB主机名；ident只是示例，不能自动假定实际存在。
- level通过显式level_map映射。本次约定1→灾难、2→严重、3→警告；真实接口模式仅允许灾难/严重/警告/一般四种目标文本。不会替缺失映射选默认值。
- alarmType自动为problem/ok，时间按Asia/Shanghai；恢复沿用已受理故障的problemTime、设备与归属，再填写recoveryTime。triggerName来自规则名称。sign不参与本地事件配对或去重。

CMDB和附加标签在首次任务登记时冻结，查询/发送时不重新读取当前资产或规则；恢复沿用已受理故障。规则字段冻结的是登记时保存内容，尚不是事件产生时的历史规则版本。没有新增告警与CMDB的隐式绑定关系、人员匹配或下游通知逻辑。

## 密钥、模式及任务

真实模式必须引用center独立密钥文件，默认platform10-v1对应 `/etc/n9e/secrets/platform10.key`，路径可覆盖；预览使用实例私有路径。页面不保存密码，不回传文件内容，只提供管理员只读状态检查。UTF-8下按problemTime去普通空格、拼接原密码、MD5并转大写生成sign。签名算法和编码已确认，真实密码由部署端单独配置，不上传Git。

本地模拟模式只允许数字回环HTTP地址，可显式使用测试签名。切换模式会清除不适用的地址/测试值；模拟故障不能作为真实恢复的前序。已有模拟配置和任务保留其原模式。

任务是向外部接口推送事件，不按本地人数复制请求。仅center worker发送。结果不明、发送中重启或超时不会自动重投，人工确认和授权重发留痕；恢复受前序故障实际投递结果约束。屏蔽、过滤和恢复开关沿用本地规则，恢复被过滤可能让1.0保留未恢复故障。
